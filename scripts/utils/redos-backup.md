Утилита резервного копирования пользовательских данных и домашних каталогов для РЕД ОС. Поддерживает интерактивный мастер и CLI-режим для запуска из терминала, скриптов, ярлыков и регламентных заданий.

## Возможности

* резервное копирование пользовательских данных через XDG-каталоги
* полный backup домашнего каталога (`HOME`)
* интерактивный режим с выбором пользователя, режима и накопителя
* CLI-режим с явными параметрами запуска
* вывод списка пользователей и подключённых USB/внешних каталогов
* проверка свободного места перед копированием
* режим проверки без запуска копирования (`--check`)
* безопасное копирование через `rsync`
* отображение прогресса копирования в виде заполняемой строки с процентами
* поддержка русских каталогов и путей
* обработка символических ссылок с учётом файловой системы накопителя
* исключение временных данных, кэшей, сокетов и спецфайлов
* логирование операций в `/tmp/redos-backup.log`

## Режимы копирования

### `data` — пользовательские данные

Копируются основные пользовательские каталоги:

* Рабочий стол
* Документы
* Загрузки
* Музыка
* Изображения
* Видео

Каталоги определяются автоматически через XDG:

```bash
~/.config/user-dirs.dirs
```

В этом режиме дополнительно исключаются приватные данные:

```text
.ssh
.gnupg
.pki
```

### `home` — полный HOME

Создаётся резервная копия всего домашнего каталога пользователя.

При этом автоматически исключаются временные и проблемные для переноса данные:

```text
.cache
.local/share/Trash
.thumbnails
.gvfs
.npm
.cargo
.steam
.var/app
thinclient_drives
.config/chromium/Singleton*
.config/google-chrome/Singleton*
.config/yandex-browser*/Singleton*
.pcsc*/pcscd.comm
*.sock
```

## Запуск

Интерактивный режим остался режимом по умолчанию:

```bash
chmod +x redos-backup-v2.4.sh
sudo ./redos-backup-v2.4.sh
```

CLI-режим включается при передаче параметров:

```bash
sudo ./redos-backup-v2.4.sh --user eduadmin --mode data --dest /mnt/backup/eduadmin --yes
```

Краткая справка:

```bash
./redos-backup-v2.4.sh --help
```

### Опции CLI

| Опция | Описание |
| --- | --- |
| `-u`, `--user USER` | Пользователь, чей профиль нужно копировать |
| `-m`, `--mode data\|home` | Режим: XDG-данные или полный HOME |
| `-d`, `--dest DIR` | Полный каталог назначения |
| `--usb DIR` | Базовый каталог накопителя, например `/run/media/user/USB` |
| `-n`, `--name NAME` | Имя папки бэкапа внутри `--usb` |
| `-y`, `--yes` | Запустить копирование без подтверждения |
| `--check` | Только проверить размер и свободное место |
| `--list-users` | Показать доступных обычных пользователей |
| `--list-usb` | Показать смонтированные USB/внешние каталоги |
| `-h`, `--help` | Показать справку |

`--dest` и связка `--usb + --name` являются альтернативными способами указать каталог назначения. Их нельзя использовать одновременно.

### Примеры CLI

Скопировать XDG-данные пользователя в готовый каталог:

```bash
sudo ./redos-backup-v2.4.sh \
  --user eduadmin \
  --mode data \
  --dest /mnt/backup/eduadmin \
  --yes
```

Сделать полный backup HOME на USB-накопитель:

```bash
sudo ./redos-backup-v2.4.sh \
  --user eduadmin \
  --mode home \
  --usb /run/media/eduadmin/USB \
  --name backup-home \
  --yes
```

Проверить объём данных и свободное место без копирования:

```bash
sudo ./redos-backup-v2.4.sh \
  --user eduadmin \
  --mode data \
  --dest /mnt/backup/eduadmin \
  --check
```

Посмотреть доступных пользователей и накопители:

```bash
./redos-backup-v2.4.sh --list-users
./redos-backup-v2.4.sh --list-usb
```

## Сценарий работы

В интерактивном режиме:

1. Выбор пользователя
2. Выбор режима резервного копирования
3. Автоматический поиск USB-накопителей
4. Выбор каталога назначения
5. Проверка свободного места
6. Подтверждение операции
7. Копирование данных с прогресс-баром
8. Вывод результата и пути к логу

В CLI-режиме те же шаги выполняются на основе переданных параметров. Если указан `--yes`, подтверждение не запрашивается. Если указан `--check`, скрипт останавливается после проверки свободного места.

## Особенности

### Проверка зависимостей

Перед началом работы скрипт проверяет наличие необходимых команд:

```text
awk
cut
df
du
findmnt
grep
ln
numfmt
rm
rsync
tail
tr
```

Если какая-либо команда не найдена, запуск прерывается до выбора данных.

### Проверка свободного места

Перед копированием выполняется расчёт размера данных и сравнение со свободным местом на накопителе. При нехватке места операция отменяется до запуска `rsync`.

Для полного бэкапа HOME расчёт размера использует те же исключения, что и последующее копирование.

### Прогресс копирования

Во время копирования отображается компактная строка прогресса:

```text
[####################                    ]  50%
```

Процент берётся из общего прогресса `rsync`, а подробный вывод операции сохраняется в лог.

### Символические ссылки

После выбора каталога назначения скрипт проверяет, поддерживает ли накопитель символические ссылки.

Если поддерживает, ссылки сохраняются как ссылки. Если не поддерживает, например на FAT/exFAT/NTFS без Linux-прав, ссылки пропускаются. Это предотвращает ошибки вида:

```text
symlink ... failed: Operation not permitted
```

Ссылки не разворачиваются в реальные каталоги. Это защищает от циклических связок вроде `Рабочий стол` ↔ `Мои Документы`, которые могут приводить к ошибке `Too many levels of symbolic links`.

### Безопасное копирование

Используется:

```bash
rsync -a
```

Копирование настроено так, чтобы:

* сохранять структуру каталогов
* учитывать поддержку символических ссылок на накопителе
* не переносить устройства, сокеты и другие спецфайлы
* продолжать работу при некритичных ошибках `rsync` с кодами `23` и `24`
* сохранять подробный лог операции

Имена папок назначения проверяются: нельзя указать пустое имя, `.`/`..` или путь со слешем при использовании `--name`.
