>Скрипт `user-migration.sh` предназначен для миграции учётной записи пользователя в операционной системе РЕД ОС.
>Автоматизирует создание нового пользователя, перенос файлов и настройку прав доступа.

## 🚀 Быстрый старт

### 1. Скачивание скрипта

**Вариант 1: Быстрый запуск через `curl`**

```bash
curl -sL https://github.com/teanrus/redos-lifehacks/releases/latest/download/user-migration.sh | sudo bash
```

**Вариант 2: Быстрый запуск через `wget`**

```bash
wget -qO- https://github.com/teanrus/redos-lifehacks/releases/latest/download/user-migration.sh | sudo bash
```

**Вариант 3: Скачивание с проверкой целостности**

```bash
cd /tmp

curl -sL https://github.com/teanrus/redos-lifehacks/releases/latest/download/user-migration.sh \
  -o user-migration.sh

curl -sL https://github.com/teanrus/redos-lifehacks/releases/latest/download/user-migration.sh.sha256 \
  -o user-migration.sh.sha256

sha256sum -c user-migration.sh.sha256
sudo bash user-migration.sh
```

### 2. Подготовка

Если скрипт скачан вручную и вы хотите запускать его как исполняемый файл:

```bash
# Сделать скрипт исполняемым
chmod +x user-migration.sh
```

### 3. Запуск

```bash
# Запустить от имени root
sudo ./user-migration.sh
```

### Шаг 3: Проверка объёма данных и свободного места

После выбора старого пользователя скрипт подсчитает размер его домашнего каталога и проверит свободное место в `/home`:

```

-------------------------------------------
📁 Каталог источника: /home/SemkinaSY
📦 Объем данных: 42GB
💽 Свободно в /home: 120GB
-------------------------------------------

✅ Свободного места достаточно для копирования данных
```

Если места недостаточно для копирования, скрипт выведет предупреждение и предложит выбор:

```
⚠️  Свободного места недостаточно для копирования всех данных.
   Рекомендуется освободить место на разделе /home и запустить скрипт повторно.

Выберите дальнейшее действие:
   1) Прекратить работу скрипта
   2) Не копировать данные, а переместить их новому пользователю

Ваш выбор (1/2): 2
⚠️  Выбран режим перемещения: исходные файлы будут удаляться после успешного переноса.
```

**Режимы переноса:**
- `копирование` — данные остаются у старого пользователя и копируются новому пользователю;
- `перемещение` — данные передаются новому пользователю, а исходные файлы удаляются после успешной передачи.

### Шаг 7: Добавление в группу wheel

Скрипт предложит добавить нового пользователя в группу администраторов:

```
📋 Шаг 3/8: Добавление в группы...

Группа 'wheel' предоставляет права администратора (доступ к sudo)

Добавить пользователя 'ivanovii' в группу 'wheel'? (y/n): y

✅ Добавлен в группу 'wheel' (sudo)
```

**Что такое wheel:**
- Группа для пользователей с правами администратора
- Позволяет выполнять команды с правами root через `sudo`
- Рекомендуется для ведущих специалистов и администраторов

**Если выбрали `n`:**
- Пользователь не будет иметь прав администратора
- Для добавления позже: `sudo usermod -aG wheel ivanovii`

### Шаг 8: Перенос файлов

Скрипт выполнит копирование или перемещение всех файлов с отображением прогресса:

```
📋 Шаг 4/8: Перенос файлов из /home/SemkinaSY/

⚠️  Перенос файлов может занять несколько минут...

sending incremental file list
./
Documents/
Documents/отчёт.docx
  1.23MB  100%   50.00kB/s    0:00:25
...
```

При обычном копировании используется:

```bash
rsync -avh --progress /home/old/ /home/new/
```

При нехватке места и выборе перемещения используется:

```bash
rsync -avh --progress --remove-source-files /home/old/ /home/new/
```

**Краткая справка по `rsync`:**
- `rsync` копирует только изменившиеся данные и умеет продолжать перенос после повторного запуска.
- `-a` включает архивный режим: сохраняет права, владельцев, группы, даты, символические ссылки и структуру каталогов.
- `-v` показывает подробный вывод, чтобы было видно, какие файлы обрабатываются.
- `-h` выводит размеры в удобном виде: KB, MB, GB.
- `--progress` показывает ход передачи крупных файлов.
- `--remove-source-files` удаляет исходные файлы после успешной передачи; каталоги при этом не удаляются, поэтому скрипт отдельно очищает пустые подпапки.

> [!tip]
> В `rsync` важен завершающий `/` у каталога-источника. Команда `rsync /home/old/ /home/new/` переносит содержимое каталога `old`, а `rsync /home/old /home/new/` создаст внутри назначения подкаталог `old`.

Подробная инструкция по применению `rsync` добавлена в Wiki: [Синхронизация через rsync](https://github.com/teanrus/redos-lifehacks/wiki/RSync-Sync).

После успешного перемещения скрипт удалит пустые подпапки в старом домашнем каталоге. Сам старый пользователь остаётся в системе до отдельного подтверждения удаления.

### Шаг 9: Очистка связки ключей GNOME Keyring

После переноса данных скрипт очищает каталог связки ключей у нового пользователя:

```bash
/home/ivanovii/.local/share/keyrings/*
```

Это нужно, чтобы у нового пользователя не появлялись постоянные запросы старой связки ключей после входа в систему. При первом запуске GNOME Keyring создаст новую связку ключей уже для нового пользователя.

## 📊 Что делает скрипт

### Этапы работы

| Шаг | Действие | Описание |
|-----|----------|----------|
| 1 | Создание пользователя | `useradd -m -c "ФИО, должность" login` |
| 2 | Установка пароля | `passwd login` |
| 3 | Добавление в группы | Запрос: добавить ли в группу `wheel` |
| 4 | Перенос файлов | Копирование через `rsync -avh --progress` или перемещение через `rsync --remove-source-files` |
| 5 | Перенос браузеров | Копирование профилей 5 браузеров; в режиме перемещения шаг пропускается, так как профили уже перенесены вместе с домашним каталогом |
| 6 | Очистка GNOME Keyring | Удаление старой связки ключей из `/home/new/.local/share/keyrings/` |
| 7 | Исправление прав | `chown -R new:new /home/new/` |
| 8 | Проверка | Вывод информации о пользователе, размера данных и сводки переноса |

Перед созданием нового пользователя скрипт также выполняет предварительную проверку: считает объём `/home/old`, сравнивает его со свободным местом в `/home` и при нехватке места предлагает остановиться или перейти в режим перемещения.

### Переносимые данные

**Домашний каталог:**
- Все файлы и папки
- Скрытые файлы (`.bashrc`, `.profile`, `.gitconfig` и др.)

**Браузеры:**
- `~/.config/google-chrome/` — Google Chrome
- `~/.config/chromium/` — Chromium
- `~/.mozilla/firefox/` — Mozilla Firefox
- `~/.config/Yandex/YandexBrowser/` — Яндекс.Браузер
- `~/.config/opera/` — Opera

**Связка ключей:**
- `~/.local/share/keyrings/` — очищается у нового пользователя после переноса, чтобы GNOME Keyring создал новую связку ключей

**SSH-ключи:**
- Сохраняются права `700` на `.ssh/` и `600` на файлы внутри

## ⚠️ Важные замечания

### Перед запуском

1. **Убедитесь, что старый пользователь вышел из системы**
   ```bash
   who  # Проверка активных сессий
   ```

2. **Закройте все браузеры** (важно для корректного копирования данных)

3. **Проверьте свободное место**
   ```bash
   df -h /home
   ```
   Скрипт также выполнит эту проверку самостоятельно и предупредит, если места недостаточно.

### Копирование или перемещение

**Копирование** — безопасный режим по умолчанию. Старый домашний каталог остаётся на месте, а данные копируются новому пользователю.

**Перемещение** доступно только как ответ на нехватку места. В этом режиме `rsync` удаляет исходные файлы после успешной передачи. Используйте его, если невозможно быстро освободить место, но нужно завершить миграцию.

> [!warning]
> При перемещении старый пользователь теряет перенесённые файлы из домашнего каталога. Перед выбором этого режима убедитесь, что старый пользователь вышел из системы и данные не используются приложениями.

### Безопасность паролей браузеров

**Google Chrome / Chromium:**
- Пароли зашифрованы с использованием GNOME Keyring
- Скрипт очищает `~/.local/share/keyrings/` у нового пользователя после переноса
- При первом входе или запуске браузера GNOME Keyring создаст новую связку ключей

**Mozilla Firefox:**
- Пароли хранятся в `logins.json` и `key4.db`
- Переносятся автоматически вместе с профилем

### Возможные проблемы

| Проблема | Причина | Решение |
|----------|---------|---------|
| Ошибка прав доступа | Запуск не от root | Используйте `sudo ./user-migration.sh` |
| Файлы заблокированы | Пользователь в системе | Завершите сессию: `pkill -u username` |
| Недостаточно места | Заполнен `/home` | Освободите место или выберите перемещение данных |
| Браузер не открывает профиль | Неверные права | `chown -R new:new ~/.mozilla/` |

