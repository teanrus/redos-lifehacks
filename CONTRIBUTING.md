# Вклад в проект

Спасибо за интерес к проекту **redos-lifehacks**! Любая помощь — от исправления опечатки до нового скрипта — приветствуется.

## Как помочь

### 1. Форкните репозиторий

```bash
git clone https://github.com/teanrus/redos-lifehacks.git
cd redos-lifehacks
```

### 2. Создайте ветку

```bash
git checkout -b feature/ваше-изменение
```

Используйте префиксы в названии ветки:

| Префикс | Назначение |
|---------|-----------|
| `feature/` | Новый скрипт или документ |
| `fix/` | Исправление ошибки |
| `docs/` | Обновление документации |
| `refactor/` | Реструктуризация кода |

### 3. Внесите изменения

См. разделы ниже по форматированию скриптов и документов.

### 4. Зафиксируйте изменения

```bash
git add .
git commit -m 'Add: описание изменений'
```

Следуйте [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/):

- `Add:` — новый файл или функционал
- `Fix:` — исправление ошибки
- `Docs:` — только документация
- `Refactor:` — реструктуризация без изменения функционала
- `Remove:` — удаление файлов

### 5. Отправьте пулл-реквест

```bash
git push origin feature/ваше-изменение
```

Откройте PR на GitHub с описанием: что изменено, зачем, как тестировалось.

## 🔧 Требования к скриптам

Каждый `.sh`-файл должен соответствовать шаблону:

```bash
#!/bin/bash
##############################################################################
# имя-скрипта.sh — Краткое описание
#
# Описание:
#   Развёрнутое описание назначения скрипта.
#
# Использование:
#   sudo ./имя-скрипта.sh [ОПЦИИ]
#
# Опции:
#   -h, --help     Справка
#   ...            Остальные опции
#
# Зависимости: bash, coreutils, ...
# Опционально: smartmontools, ...
##############################################################################

set -euo pipefail

# ─── Цвета ───────────────────────────────────────────────────────────────
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
BLUE='\033[0;34m'
CYAN='\033[0;36m'
NC='\033[0m'

# ─── Функции ─────────────────────────────────────────────────────────────
# Каждая логическая операция — отдельная функция

main() {
    # Точка входа
}

main "$@"
```

### Правила написания скриптов

| Правило | Пример |
|---------|--------|
| `set -euo pipefail` | Всегда в начале |
| Проверка root | Если нужныются привилегии: `if [ "$(id -u)" -ne 0 ]; then ...` |
| Проверка зависимостей | `command -v smartctl &>/dev/null || { echo "Установите smartmontools"; exit 1; }` |
| Цитирование переменных | Всегда `"$переменная"`, а не `$переменная` |
| Цветной вывод | Используйте константы цветов |
| Функции | Разделяйте логику на функции с комментариями `# ─── Секция ──` |
| Совместимость | Указывайте: РЕД ОС 7.x ✅, РЕД ОС 8.x ✅ |

### Требования к релизу

Каждый новый или изменённый скрипт должен быть:

1. **Приаттачен к GitHub Release** — чтобы работал `curl -sL .../download/*.sh`
2. **Добавлен в CHANGELOG.md** — в секцию `[Невыпущенное]`
3. **Связан с `.md`** — рядом лежит руководство с описанием и ссылками

## 🚀 Автоматическая публикация в Releases

При push `.sh` файлов в ветку `main` автоматически срабатывает GitHub Actions workflow:

1. **Вычисляется SHA256** для каждого скрипта
2. **Создаётся/обновляется Release** с тегом из CHANGELOG.md
3. **Прикрепляются файлы**: скрипты + `.sha256` файлы для проверки целостности
4. **Обновляется описание релиза** с таблицей контрольных сумм

### Как это работает

```bash
push .sh → GitHub Actions → sha256sum → Release + .sha256
```

### Ручной запуск

Можно запустить публикацию вручную через **GitHub Actions → Auto Release Scripts → Run workflow**:

| Параметр | Значение | Описание |
|----------|----------|----------|
| `tag` | `v1.1` | Тег нового релиза |

### Проверка целостности скриптов

После скачивания из Release можно проверить контрольную сумму:

```bash
# Скачиваем скрипт и .sha256
curl -sL https://github.com/teanrus/redos-lifehacks/releases/download/v1.0/install-cryptopro.sh -o install-cryptopro.sh
curl -sL https://github.com/teanrus/redos-lifehacks/releases/download/v1.0/install-cryptopro.sh.sha256 -o install-cryptopro.sh.sha256

# Проверяем
sha256sum -c install-cryptopro.sh.sha256
# install-cryptopro.sh: OK
```

## ✅ Чеклист перед PR

Перед отправкой проверьте:

- [ ] Скрипт проходит `bash -n script.sh` (синтаксис)
- [ ] Скрипт содержит `#!/bin/bash` и `set -euo pipefail`
- [ ] Скрипт совместим с РЕД ОС 7.3 и/или 8.0
- [ ] Рядом со скриптом есть `.md`-документ
- [ ] CHANGELOG.md обновлён (в секцию `[Невыпущенное]`) — **тег релиза берётся отсюда**
- [ ] В `.md` указаны совместимость и требования
- [ ] Нет дубликатов — один скрипт в одном месте, остальные — ссылки
- [ ] Коммиты следуют формату Conventional Commits

> [!note]
> **Автоматическая публикация**: при push `.sh` файлов в `main` GitHub Actions автоматически прикрепит скрипты к Release и создаст `.sha256` файлы. Ручное добавление в Release больше не требуется.

## 📋 Релизы

### Автоматический процесс

1. Обновить CHANGELOG.md: перенести `[Невыпущенное]` → `## [vX.Y.Z] — ГГГГ-ММ-ДД`
2. Запушить изменения: `git push origin main`
3. **GitHub Actions автоматически**:
   - Вычислит SHA256 для всех `.sh` файлов
   - Создаст/обновит GitHub Release с тегом `vX.Y.Z`
   - Прикрепит скрипты + `.sha256` файлы к релизу
   - Обновит описание релиза с таблицей контрольных сумм

### Ручной запуск (опционально)

Если нужно создать релиз с конкретным тегом:

1. GitHub Actions → **Auto Release Scripts** → **Run workflow**
2. Указать тег (например `v1.1.1`)
3. Workflow создаст релиз со всеми скриптами

> [!note]
> Тег релиза автоматически берётся из CHANGELOG.md (последняя запись `## [vX.Y]`).
> Если тега нет — используется последний git-тег или `v1.1.1` по умолчанию.
